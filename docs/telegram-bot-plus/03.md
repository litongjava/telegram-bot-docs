# 并发、限流与退出

这一页说明 telegram-bot-plus 怎样处理并发。写业务代码时要遵守这里的约定。

## 消息处理顺序

`LongPollingMultiThreadUpdateConsumer` 用虚拟线程处理更新：

- **同一聊天按接收顺序处理**，上一条处理完才处理下一条。
- **不同聊天可以并发**，一个聊天的慢请求不会阻塞其他聊天。
- **异常不影响后续消息**：业务处理抛出的 `Exception` 被捕获并写入日志，队列继续处理。

因为同一聊天串行处理，一个慢操作（比如等模型回复）会让这个聊天的后续消息排队。

聊天的归属按以下顺序确定：消息、频道帖子或编辑过的消息所在的聊天；回调查询所在消息的聊天；没有消息的回调按用户；其他更新按更新 ID，各自独立。

## 媒体组

Telegram 把相册拆成多条更新，并且可能分布在多个轮询批次中。消费者按 `media_group_id` 聚合，最后一条到达后静默 300 毫秒，再调用 `consumeGroup`。

- 这只是聚合策略：Telegram 没有“媒体组完成”事件，间隔超过 300 毫秒的更新可能被分到下一组。
- 聚合期间，同一聊天的后续文本会排在媒体组之后，顺序不变。

## 发送限流

通过 `TelegramClientCan` 发送时会自动限流，业务代码不用自己等待：

| 范围 | 频率 |
| --- | --- |
| 全局 | 约每秒 30 次 |
| 私聊（正数聊天 ID） | 每秒 1 次 |
| 群组和频道（负数聊天 ID 或 `@` 用户名） | 每 3 秒 1 次 |

闲置 5 分钟的聊天状态会被自动清理。`getMe` 不限流；`deleteMessage`、`getChat` 等只受全局限制。

需要自己发送请求时，先获取许可：

```java
RateLimiterManager.acquire(chatId);           // 同步等待
RateLimiterManager.acquireAsync(chatId);      // 返回 CompletableFuture<Void>
```

`acquireOf100()` 和 `acquireOf100Async()` 为了兼容保留，现在同样只受全局限制。

## 失败重试

同步和异步方法共用一套重试逻辑：

- 只有带有效 `retry_after` 的 429 响应才会重试，按服务端要求的时间等待，最多重试 3 次。
- 其他错误和重试耗尽后的错误都会抛给调用方。
- 取消异步任务时，会同时取消等待和进行中的请求。
- 同步等待被中断时，会恢复线程的中断标记。

```java
// 同步：失败时抛出异常
Message message = TelegramClientCan.execute(SendMessageUtils.text(chatId, "hello"));

// 异步：返回 CompletableFuture
TelegramClientCan.executeAsync(SendMessageUtils.text(chatId, "hello"))
    .exceptionally(error -> {
      log.error("send failed", error);
      return null;
    });
```

## 退出顺序

应用退出时按这个顺序关闭：

1. 关闭长轮询，不再接收新更新。
2. 调用消费者的 `close()`。它会立即交出聚合中的媒体组，并最多等待 10 秒让处理中的消息完成。
3. 调用 `RateLimiterManager.shutdown()`。
4. 关闭自己创建的 HTTP 客户端。

关闭后的对象不能再次使用，消费者关闭后再收到更新会抛出 `IllegalStateException`。

```java
HookCan.me().addDestroyMethod(() -> {
  try {
    application.close();
  } catch (Exception error) {
    log.warn("Failed to close Telegram polling", error);
  }
  consumer.close();
  RateLimiterManager.shutdown();
  BotHttpClient.close();
});
```

## 读取用户和聊天

`TgUserUtils.getUserId(update)` 返回发送者 ID，没有发送者时返回 `null`。**它不是聊天 ID**，回复时要从消息或回调消息读取聊天 ID：

```java
Long chatId = update.getMessage().getChatId();
Long userId = TgUserUtils.getUserId(update);
```
